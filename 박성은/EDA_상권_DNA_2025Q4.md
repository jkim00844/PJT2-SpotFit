# 2025년 4분기 상권 DNA 예비분류 EDA

## 이 파일의 범위

`상권_DNA_예비분류_2025Q4.xlsx`의 원천과 `PJT2-SpotFit/data/raw`와의 중복 여부를 확인했다. 예비분류 엑셀 자체는 저장소에 복사하지 않았다. 이 문서는 원천 데이터 확인과 다음 분석을 위한 개인 작업 기록이다.

## 결론

- 예비분류 엑셀의 분석 단위는 **2025년 4분기 상권 1,565개**다. 상권별 매출이 존재하는 곳만 포함하며, `상권_코드`는 중복되지 않는다.
- 엑셀의 근거 자료는 `서울_상권분석_대시보드.xlsx`의 `01_상권랭킹` 시트다. 두 파일의 1,565개 상권 코드와 주요 지표는 모두 일치한다.
- 주요 수치의 원천은 현재 저장소의 상권 원천 CSV와 겹친다. **원천 CSV에서 다시 계산할 수 있으므로 엑셀을 원천 데이터로 중복 적재할 필요는 없다.** 엑셀은 분류 아이디어와 검토 결과로 활용한다.
- 예비분류는 창업 추천 결과나 확정된 상권 유형이 아니다. `S/G` 성장 여부는 전부 미검증이다.

## 원천 데이터와 계산

| 예비분류 엑셀 열 | 현재 저장소의 원천 | 재현 방법 |
|---|---|---|
| `상권코드`, `상권명`, `상권유형`, `자치구`, `행정동` | `data/raw/상권/OA-15560_영역_상권.csv` | `상권_코드`로 연결. 행정동 이름은 화면 표시용으로 일부 정제됨 |
| `Q4추정매출(원)` | `data/raw/상권/OA-15572_추정매출_상권.csv` | `기준_년분기_코드=20254`에서 업종별 `당월_매출_금액`을 상권별 합산 |
| `Q4매출건수`, `Q4객단가(원)` | 같은 추정매출 CSV | 업종별 `당월_매출_건수` 합계, 객단가 = 매출액 / 매출건수 |
| `평일매출비중` | 같은 추정매출 CSV | 상권별 `주중_매출_금액` 합계 / 전체 매출액 |
| `2030매출비중` | 같은 추정매출 CSV | (`연령대_20_매출_금액` + `연령대_30_매출_금액`) 합계 / 전체 매출액 |
| `직장인구/ha` | `data/raw/상권/OA-15569_직장인구_상권.csv`와 영역 CSV | 2025Q4 `총_직장_인구_수` / (`영역_면적`㎡ / 10,000) |
| `기존_상권DNA` | `서울_상권분석_대시보드.xlsx`의 `01_상권랭킹` | 기존 대시보드에서 복사한 해석 레이블. 원천 CSV의 관측 열이나 독립 검증용 정답이 아님 |

`L/V_잠정`, `E/P_잠정`, `2축_잠정코드`는 위 관측값을 기준값과 비교한 **이 엑셀의 파생 분류**다. `01_분류기준` 시트의 전체 중앙값과 상권유형별 객단가 중앙값을 사용한다.

## 중복 여부 검증

2025Q4 원천 추정매출 파일의 **업종별 21,333행**을 `상권_코드`별로 합치면 1,565개 상권이 나온다. 예비분류 엑셀의 1,565개 코드와 정확히 같다.

| 확인 항목 | 결과 |
|---|---:|
| 예비분류 ↔ 기존 대시보드 상권코드 일치 | 1,565 / 1,565 |
| 매출액·매출건수·객단가·평일매출비중·2030매출비중 재계산 불일치 | 0건 |
| 직장인구/ha 재계산 불일치 | 0건 (값이 있는 1,559개 기준) |
| 직장인구/ha 결측 | 6건 |
| 상권명·상권유형·자치구명 불일치 | 0건 |
| 행정동 표시 이름 불일치 | 35건. 원천의 `?`를 `·`로 고친 표기 차이 |

매출은 **서울시의 추정매출**이며 점포별 확정 회계 매출이 아니다. 또한 예비분류의 `Q4추정매출`은 업종별 행을 합산한 값이므로, 원천 파일 전체 기간 합계와 혼동하지 않는다.

## 현재 예비분류의 상태

| 분류 | 상권 수 |
|---|---:|
| LE | 298 |
| LP | 164 |
| VE | 188 |
| VP | 273 |
| 판정보류 | 642 |
| 합계 | 1,565 |

642개(약 41%)가 판정보류다. `S/G_검증`은 1,565개 모두 `미검증`이다.

- **L/V**는 평일매출 비중과 직장인구 밀도가 둘 다 중앙값보다 높은지/낮은지를 보는 대리지표다. 실제 거주자와 방문객의 비율을 직접 측정하지 않는다.
- **E/P**는 같은 상권유형 안에서 객단가가 중앙값보다 높은지 보는 대리지표다. 소비자의 가격민감도나 프리미엄 선호를 직접 측정하지 않는다.
- `기존_상권DNA`는 같은 대시보드에서 가져온 레이블이므로, 새 분류의 정확도를 검증하는 독립 정답으로 쓰지 않는다.

## PJT2-SpotFit 분석에 쓰는 방법

1. 엑셀의 4개 예비군은 **가설과 시각화 색상**으로 사용한다. 추천 모델의 정답 레이블로 바로 넣지 않는다.
2. `OA-15568_길단위인구_상권.csv`, `OA-15584_상주인구_상권.csv`를 `상권_코드`로 붙여 L/V 해석을 검증한다. 직장인구 결측 6건은 0으로 채우지 않는다.
3. 2025Q1~Q4 `OA-15572_추정매출_상권.csv`로 상권별 분기 매출 변화를 본다. **2024년 대비 성장률(YoY)** 은 현재 2025년 원천 패키지만으로 계산할 수 없다.
4. 행정동 단위 `OA-22166_소비_행정동.csv`와 비교하려면 먼저 `OA-15560_영역_상권.csv`의 `행정동_코드`로 상권을 행정동에 연결한다. 상권 1개 행과 행정동 1개 행을 그대로 1:1 합치지 않는다.
5. 다음 EDA에서는 상권유형별 객단가 분포, 직장인구 밀도와 평일매출 비중의 산점도, 642개 판정보류 원인을 우선 확인한다.

위 두 엑셀은 현재 저장소에 없으므로 다른 팀원이 열려면 별도 공유가 필요하다. 주요 관측 지표는 저장소 원천 CSV에서 재현할 수 있다.

원본 엑셀과 원천 CSV를 변경하지 않았다. 위 수치 대조는 현재 저장소의 2025년 원천 파일과 이전 대시보드의 저장된 값 기준이다.
